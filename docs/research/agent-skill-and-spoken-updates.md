# Agent skills and spoken task updates

Checked against first-party documentation and upstream repositories on 2026-11-22. SmallTalkAI CLI speech playback on Linux and Windows is assumed for this research. Host integrations and audio playback were untested.

## Skill discovery and installation

An Agent Skill is a directory with `SKILL.md`, required `name` and `description` frontmatter, and optional scripts, references, and assets. Hosts can show the description before reading the instructions. The format leaves discovery directories, invocation, permissions, and lifecycle events to each host. [Agent Skills specification](https://agentskills.io/specification)

| Host | Project and personal discovery | How to verify discovery |
| --- | --- | --- |
| Codex | `.agents/skills/` from the working directory up to the repo root, and `~/.agents/skills/` for the user. Supports symlinked skill folders. | Use `/skills` or type `$` in the CLI. Try a restart if the install does not appear. OpenAI's catalog uses the bundled `$skill-installer`. [Codex skills guide](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills), [OpenAI skills catalog](https://github.com/openai/skills) |
| Claude Code | `.claude/skills/` in the project and `~/.claude/skills/` on the local machine. Plugins can also carry a `skills/` directory. | Check the `/` menu and invoke `/<skill-name>`. Claude can also load relevant skills automatically. [Claude Code skills](https://code.claude.com/docs/en/skills) |
| Cursor | `.agents/skills/` or `.cursor/skills/` in the project and their `~/` equivalents on the local machine. Also reads Claude and Codex compatibility directories. | Look in Customize or invoke `/<skill-name>` in Agent chat. Cursor's GitHub import UI installs skills through a plugin marketplace. [Cursor skills](https://cursor.com/docs/skills) |
| OpenCode | `.opencode/skills/` in the project and `~/.config/opencode/skills/` for the user. Also searches project and user `.claude/skills/` and `.agents/skills/`. | Ask the agent to load the named skill with its `skill` tool. Check the selected agent's skill permissions if it is missing. [OpenCode skills](https://opencode.ai/docs/skills/) |

Vercel's `skills` CLI supports all four hosts. `npx skills find` searches the catalog and `npx skills add <owner>/<repo> --list` previews a source. Install a selected skill with `--skill <name>` and explicit `--agent` targets. Project scope is the default and `--global` selects user scope. The installer can link host directories to a canonical copy or use `--copy` where links are inconvenient. Vercel publishes its own `agent-skills` collection through this CLI, while Anthropic's official collection also supports `/plugin marketplace add anthropics/skills`. OpenAI's catalog demonstrates installing individual skills by GitHub URL. [Vercel CLI reference](https://github.com/vercel-labs/skills/blob/main/docs/commands.md), [Vercel skill collection](https://github.com/vercel-labs/agent-skills), [Anthropic skill collection](https://github.com/anthropics/skills), [OpenAI skills catalog](https://github.com/openai/skills)

**SmallTalkAI recommendation.** Publish one `skills/smalltalkai/SKILL.md` with an explicit opt-in workflow for spoken updates and document the manual copy destinations. Offer user-scope installation through Vercel's CLI as a convenience. Pin the package ref for reproducible installs and verify discovery in fresh sessions on both operating systems. Keep the shared frontmatter to the standard fields. If host-native packaging becomes useful, have each package reference the same skill source and make automatic notifications a separate opt-in.

## What to say

Google's conversation design guidance favors acknowledging completed actions when the result would otherwise be unclear. Alexa recommends brief sentences with simple structure. Home Assistant Assist demonstrates an announcement sent to a selected speaker when a task finishes, and its Linux Voice Assistant can play an optional cue before speaking. [Google confirmations](https://developers.google.com/assistant/conversation-design/confirmations), [Alexa Be Brief](https://developer.amazon.com/en-US/alexa/alexa-haus/design-principles/be-brief), [Assist announcement action](https://www.home-assistant.io/actions/assist_satellite.announce/), [Linux Voice Assistant behavior](https://github.com/OHF-Voice/linux-voice-assistant/blob/main/docs/behavior.md)

**SmallTalkAI recommendation.** Speak one short sentence by default, with a second only if the listener needs to act. Lead with the verified outcome or blocker. For example, “The settings fix passed all tests,” or “The build stopped because a dependency is missing.” Keep paths, commands, logs, and sensitive details in the written reply. Use the user's chosen language and provide a mute control. Announce progress only when requested or when the user needs to intervene.

## Background execution and playback

| Host | Candidate for optional automatic delivery |
| --- | --- |
| Codex | `Stop` can provide `last_assistant_message`. Review and trust command hooks via `/hooks`. A turn ending still needs a task-completion check. [Codex hooks](https://learn.chatgpt.com/docs/hooks#stop) |
| Claude Code | `Stop` supplies `last_assistant_message` and can expose in-flight `background_tasks`. `StopFailure` handles API errors separately. In `claude -p`, teardown cancels async hooks that are still running. [Claude Code hooks](https://code.claude.com/docs/en/hooks#stop), [Async hook behavior](https://code.claude.com/docs/en/hooks#run-hooks-in-the-background) |
| Cursor | `afterAgentResponse` supplies response text. `stop` supplies `completed`, `aborted`, or `error` for the agent loop. Correlate the events before announcing an outcome. Project hooks can run on Cloud Agents, where playback would execute remotely. [Cursor hooks](https://cursor.com/docs/hooks), [Cursor Cloud Agents](https://cursor.com/docs/cloud-agent) |
| OpenCode | A plugin subscriber executes in the server process. Verify events against the supported OpenCode release. Upstream reproduced V2 builds where `session.idle` never arrived and `session.execution.succeeded`, `.failed`, and `.interrupted` did. [OpenCode server plugins](https://opencode.ai/docs/build/plugins/server), [Upstream event report](https://github.com/anomalyco/opencode/issues/55358) |

Start with a local foreground call after task verification. Invoke the installed `smalltalkai` on Linux or `smalltalkai-ctl.exe` on Windows with `media speak --stdin`, passing one UTF-8 message as data. Foreground playback waits for completion, so bound the call and preserve the written result if speech is denied, unavailable, or times out. Keep host permissions intact. For background delivery, enqueue a short, expiring request to a user-session component and deduplicate by task or turn ID. A stop event can also mean the agent is waiting for work or user input. [SmallTalkAI CLI](../cli.md#media), [Codex permissions](https://learn.chatgpt.com/docs/agent-approvals-security), [Claude Code Stop input](https://code.claude.com/docs/en/hooks#stop-input)

Play in the listener's desktop session. Linux PipeWire normally uses the socket in `XDG_RUNTIME_DIR`. Windows services run in session 0, and job objects can terminate subprocesses when their last handle closes. A cloud worker, remote server, or CI runner needs an explicit return path to the desktop for audible delivery. Use written status when that path is absent. For a later integration, check success, blocked and cancelled runs, pending background work, replayed events, missing audio, and host shutdown on both operating systems. [PipeWire daemon](https://docs.pipewire.org/page_daemon.html), [Windows interactive services](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services), [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [Codex execution environments](https://learn.chatgpt.com/docs/environments/modes), [Claude Code cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)

## Codex CLI trial

In a fresh Git project, Codex found the installed skill from a plain request to speak a result. It used the absolute executable path and sent two short sentences. The first draft asked Codex to use a temporary file. Its shell rejected a cleanup command, so the skill now offers UTF-8 stdin.

The sandbox stopped the first detached player before it could synthesize speech. With playback handed to the running desktop Reader, Codex exited while the test provider held its first response. Both chunks reached the test audio device after the provider released them. A second run with Reader closed reported the missing Reader and still gave the written result.
