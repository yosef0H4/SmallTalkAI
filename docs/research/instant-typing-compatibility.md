# Instant Type compatibility

Source review on 2026-11-27 against the current checkout. Application behavior and transcript length limits were not tested on a desktop.

## Windows

- The shell leaves `SendMode` at its default, `Input`. AutoHotkey documents an approximate 5,000-character limit that varies with Windows version and settings. Instant Type sends at most 256 UTF-16 code units per `SendText` call, keeping surrogate pairs and CRLF together. A one-shot timer schedules the next chunk. A successful call does not confirm that the target accepted the text. [SmallTalkAI typing](../../ahk/lib/Typist.ahk) · [AutoHotkey SendMode](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/lib/SendMode.htm#L38) · [AutoHotkey SetTimer](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/lib/SetTimer.htm#L34) · [Microsoft UTF-16 guidance](https://learn.microsoft.com/en-us/windows/win32/intl/surrogates-and-supplementary-characters)
- `SendText` sends ordinary text as Unicode input. Microsoft documents that `KEYEVENTF_UNICODE` puts `VK_PACKET` in the foreground thread’s queue and `TranslateMessage` produces `WM_CHAR`. A field that consumes physical keys or scan codes can therefore behave differently from a standard text field. AutoHotkey explicitly maps LF, CR or CRLF within one call to Enter, Tab to Tab and backspace to Backspace. These keys can submit a prompt, change focus or delete text. Paced mode sends one `SubStr(..., 1)` per call, so a CRLF that reaches it intact becomes two Enter sends. [AutoHotkey Send](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/lib/Send.htm#L85) · [AutoHotkey Unicode handling](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/lib/Send.htm#L518) · [Microsoft KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput#remarks)
- Pacing gives a burst-sensitive receiver more time between sends and uses the same Unicode input mechanism. Both speeds check the target window and wait for physical modifiers to clear between sends. Windows UIPI restricts injection into higher-integrity targets, including an injected paste shortcut from a lower-integrity sender. [Recording target](../../ahk/smalltalkai.ahk#L104) · [Delivery checks](../../ahk/lib/Typist.ahk) · [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput#remarks)

## Linux

- The shell sends a local reader request through the authorized RemoteDesktop `ConnectToEIS` session. Both typing speeds require the compositor’s EIS text capability. Instant sends UTF-8 chunks of at most 254 bytes at code-point boundaries, one commit per frame. Paced sends one Unicode scalar at a time. Both send LF and Tab as keyboard keys and skip CR. The broker rejects text over 48 KiB before dispatch. Its EIS sync checks compositor progress, without verifying insertion into the field. [Shell routing](../../src/bin/smalltalkai_linux.rs#L2750) · [Chunking](../../reader/crates/smalltalkai-reader/src/portal_input.rs#L53) · [Size guard](../../reader/crates/smalltalkai-reader/src/portal_input.rs#L126) · [EIS dispatch](../../reader/crates/smalltalkai-reader/src/portal_input.rs#L543) · [Portal lifecycle](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html#session-lifecycle) · [EIS text protocol](https://libinput.pages.freedesktop.org/libei/interfaces/ei_text/index.html#ei_textutf8)
- KDE’s KWin source provides EIS text when built with libeis 1.6 support. It routes commits through the focused text-input client where available, otherwise attempting keysym-to-keycode conversion. The inspected GNOME Mutter EIS implementation advertises keyboard capability without text capability. A working paste shortcut therefore does not establish Type support. Pacing can help a receiver that accepts individual commits but mishandles batches. It cannot add the missing capability or keep the target focused. The broker captures focus at delivery time and rechecks the window per unit where a KDE or X11 observer is available. [KWin EIS device](https://github.com/KDE/kwin/blob/master/src/plugins/eis/eisbackend.cpp#L192) · [KWin commit routing](https://github.com/KDE/kwin/blob/master/src/inputmethod.cpp#L474) · [Mutter EIS seat](https://github.com/GNOME/mutter/blob/main/src/backends/meta-eis-client.c#L1070) · [Focus observers](../../reader/crates/smalltalkai-reader/src/read_along_capture.rs#L705)

## What Smart Paste can solve

An app rule can select a paste chord the target accepts. The clipboard carries the transcript as one payload, avoiding the Windows Unicode packet stream, Linux EIS text capability and separate Enter/Tab injection. The destination still controls how it handles multiline clipboard content. Smart Paste selects a route by app identity before delivery. On Linux the automatic paste chord still requires authorized EIS keyboard input, and on both platforms it still depends on the focused field accepting paste. ## Bot checks and account enforcement (2026-11-27)

This source review found no public incident establishing that ordinary clipboard-free dictation alone caused a web or game account suspension or ban on Windows or Linux. The examples below are specific to the products and policies cited. No live services were tested.

- **Web posting restriction.** Discourse can silence eligible new users when the measured composition time for a first post is too short. A forum operator reported that short replies were held for review and users were silenced. Discourse support reproduced the 2019 case with clipboard paste and traced it to a reply being counted as the first post. The original users’ input methods remain unknown. [Discourse source](https://github.com/discourse/discourse/blob/main/lib/new_post_manager.rb) · [Operator report and support reproduction](https://meta.discourse.org/t/user-was-banned-for-posting-a-reply-within-3-seconds/128823)
- **Verification challenge.** In 2008, TypeRacer documented requiring a CAPTCHA typing test after unusually fast race scores, including those of legitimate fast typists. Wispr Flow’s CAPTCHA documentation concerns its own account workflows. Its separate Windows insertion documentation describes clipboard paste. [TypeRacer announcement](https://blog.typeracer.com/2008/05/19/new-speedometer-and-improved-cheat-protection/) · [Wispr Flow CAPTCHA](https://docs.wisprflow.ai/articles/8527688318-fix-captcha-issues-blocking-login-downloads-or-subscriptions) · [Wispr Flow insertion](https://docs.wisprflow.ai/articles/1621472516-flow-fails-to-detect-text-fields-or-inserts-incorrectly-on-non-qwerty-keyboard-layouts)
- **Game chat and gameplay.** OldOrbit documents rejecting messages and escalating to chat mutes for sending messages too quickly. Valve documents CS2 match kicks for gameplay input automation. A World of Warcraft player reported that their Windows speech-to-text add-on sent text successfully and asked whether it could incur a ban. The thread contains no enforcement outcome. [OldOrbit chat rules](https://wiki.oldorbit.com/en/baslangic/sohbet-ve-gruplar/) · [Valve announcement](https://store.steampowered.com/news/posts/?appids=730&enddate=1724103958&feed=steam_community_announcements) · [WoW player report](https://us.forums.blizzard.com/en/wow/t/wow-voice-to-text-addon/2373069)
- **Input delivery failures.** Nuance documents Windows Dragon add-in failures that can prevent text entry. A Vocalinux user reproduced missing dictation on Kubuntu KDE Wayland and traced it to IBus commits failing to reach the compositor. These sources describe local input failures with no account action reported. [Nuance support](https://www.nuance.com/products/help/dragon161/dragon-for-pc/enx/dpg-cp/Content/DialogBoxes/problems/compat_mode_msg.htm) · [Vocalinux issue](https://github.com/VocaHQ/vocalinux/issues/574)
