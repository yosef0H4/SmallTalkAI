# Responsive Settings layout audit

Use Playwright geometry checks for the broad matrix, a few screenshot baselines for visual regressions, and a small smoke test in each shipped desktop WebView.

## Existing coverage

The Chromium localization suite already checks document overflow across six routes, `en`/`ar`, light/dark, and 360/768/1280 CSS px at 900 px tall. The overhaul suite also checks main-pane overflow and pinned navigation. Both can export screenshots for review. The Tauri window opens at 1024×760 with a 320×360 minimum. See [localization](../../scripts/test-settings-localization.cjs), [overhaul](../../scripts/test-settings-overhaul.cjs), and the [desktop window builder](../../desktop/settings/src/main.rs).

## What each check catches

| Check | Use in Settings | Limits and evidence |
| --- | --- | --- |
| Playwright geometry and interaction | Check the document and inner pane for horizontal overflow. Assert containment and expected alignment for the Save bar, last form control, and open dropdown or dialog. Scroll to the last control and exercise it to catch clipping or a sticky footer intercepting input. | `boundingBox()` is viewport-relative and changes with scroll. A box can exist even when another element covers it. Use app-specific assertions and ordinary clicks. [Locator API](https://playwright.dev/docs/api/class-locator#locator-bounding-box), [actionability](https://playwright.dev/docs/actionability), [CSSOM View](https://drafts.csswg.org/cssom-view/#dom-element-scrollwidth) |
| Playwright Test screenshot snapshots | Compare viewport or component images for wrapping, Arabic font rendering, theme styling, and overlays. Use a loaded fixture, settled fonts, disabled animations, and a fixed browser/OS/font/scale environment. | The current `page.screenshot()` captures evidence. `toHaveScreenshot()` adds baseline comparison and diff output. Review baseline changes deliberately and keep baselines specific to their rendering environment. [Visual comparisons](https://playwright.dev/docs/test-snapshots), [screenshot assertion](https://playwright.dev/docs/api/class-pageassertions#page-assertions-to-have-screenshot-1) |
| axe, role assertions, and keyboard checks | Run `@axe-core/playwright` on rendered states in both themes for issues such as missing labels and detectable contrast failures. Use role or ARIA snapshot assertions for accessible names and expanded states. Tab through the compact UI and check that focus stays visible and dialogs return it. | Automated accessibility checks cover a subset of issues. Geometry and screenshots supply separate evidence about clipping, alignment, and appearance. [Accessibility testing](https://playwright.dev/docs/accessibility-testing), [ARIA snapshots](https://playwright.dev/docs/aria-snapshots) |

## Practical matrix

- **Geometry.** Keep the existing six-route matrix. Add 320×360 and 1024×760 on high-risk routes. Probe 699/700/701 and 1119/1120/1121 CSS px at a fixed tall height, then 719/720/721 px tall at a fixed width above 1120 to isolate the height breakpoint. Exercise narrower component breakpoints only on their routes. The 320 px width also matches WCAG's vertical-content reflow reference. A viewport sweep alone leaves zoom behavior and functional access to verify. [Stylesheet](../../web/settings/src/app.css), [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- **Screenshots.** Start with all four `en`/`ar` × light/dark combinations at 360 px on a dense edited form with its Save bar visible. Add one default-size view and one minimum-size overlay with long Arabic labels and mixed-direction values. Drive the app's language and theme controls, then assert root `lang` and `dir`. Emulate light/dark system preferences separately for Auto theme. [Settings root state](../../web/settings/src/App.svelte), [W3C RTL guidance](https://www.w3.org/International/questions/qa-html-dir), [Playwright emulation](https://playwright.dev/docs/emulation)

## WebKit and native smoke

Run the same fixture against Playwright WebKit at minimum and default sizes for early engine coverage. Playwright ships a patched WebKit build. The packaged app uses the system WebKitGTK on Linux and Edge WebView2 on Windows, so run a separate native smoke at the same sizes. Check actual resize limits, compact navigation, an RTL dialog or dropdown, and keyboard access to Save after scrolling. Record the OS, WebView version, and display scale. For automation, Tauri documents `tauri-driver` with `WebKitWebDriver` and an Xvfb CI example on Linux, and a matching Edge driver on Windows. Use the installed package for real desktop checks. [Playwright WebKit](https://playwright.dev/docs/browsers#webkit), [Tauri WebView versions](https://v2.tauri.app/reference/webview-versions/), [driver setup](https://v2.tauri.app/develop/tests/webdriver/manual-setup/), [Tauri CI](https://v2.tauri.app/develop/tests/webdriver/ci/), [project testing guide](../testing.md)
