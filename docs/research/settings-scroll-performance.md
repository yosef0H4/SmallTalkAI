# Models catalog scrolling in WebKitGTK

Start by removing `content-visibility: auto` and `contain-intrinsic-block-size` from the catalog rows. Keep the initial 30 results and the **Show more** button, which adds 30 at a time. Scrolling alone adds no rows in Svelte. The current CSS can defer rendering the contents of rows already in the DOM, making it the first variable to test for the reported pop-in. Eager rendering shifts that work to opening or filtering the catalog and clicking **Show more**. The performance cost and cause of the pop-in still need a native trace. [Models source](../../web/settings/src/pages/Models.svelte#L140), [CSS Containment](https://drafts.csswg.org/css-contain-2/#content-visibility)

## Why rows can appear late or shift

- `content-visibility: auto` lets the engine skip offscreen descendants and lay them out and paint them as they approach the viewport. The browser chooses the distance. While a row is skipped, `auto 42px` supplies a 42 px fallback for its **inner** block size until it has a remembered rendered size. Wrapped text, localized labels, progress, and expanded errors can make actual sizes differ from that estimate. A better estimate can reduce scroll geometry changes on first reveal, while the work to reveal the contents still happens during scroll. [CSS Containment](https://drafts.csswg.org/css-contain-2/#cv-auto), [CSS Box Sizing](https://drafts.csswg.org/css-sizing-4/#intrinsic-size-override), [Models source](../../web/settings/src/pages/Models.svelte#L147)
- Paint containment persists even for visible rows and clips descendant visual overflow. Check focus outlines and any help content that extends past the row edge. WebKit has reports of scroll jank on re-entry and stale zero-height content in Safari. Verify on WebKitGTK before attributing the Linux behavior to either bug. [CSS paint containment](https://drafts.csswg.org/css-contain-2/#containment-paint), [WebKit bug 318216](https://bugs.webkit.org/show_bug.cgi?id=318216), [WebKit bug 321501](https://bugs.webkit.org/show_bug.cgi?id=321501)

## Profile the native Settings window

1. Record the distro's WebKitGTK runtime version and use an isolated Tauri debug window. Open Web Inspector with **Inspect Element** or **Ctrl+Shift+I**. Tauri requires its `devtools` Cargo feature for production builds with the inspector. The Linux window uses the system WebKitGTK, so capture the trace there. [Tauri WebView versions](https://v2.tauri.app/reference/webview-versions/), [Tauri debugging](https://v2.tauri.app/develop/debug/#webview-console), [Simple STT test setup](../testing.md#browser-settings-coverage)
2. Compare the current CSS with both declarations disabled in the Inspector. Use the same data and window size. Record first scroll and repeated fast wheel or touchpad passes in both directions, then repeat after clicking **Show more** several times. In **Timelines → Layout & Rendering** and **Frames**, look for long frames and layout or paint bursts at row entry. Compare opening, filtering, and expanding the list as well, since those interactions may absorb the eager-rendering cost. Use **Layers** paint flashing separately to see what repaints. If frame costs remain unclear, WebKitGTK also supports engine tracing with Sysprof when built with that support. [Web Inspector Timelines](https://webkit.org/web-inspector/timelines-tab/), [Web Inspector Layers](https://webkit.org/web-inspector/layers-tab/), [WebKitGTK Sysprof integration](https://webkitgtk.org/2024/10/04/webkitgtk-2.46.html)

## Keep the retro styling

Retain solid panel fills, the existing one-pixel row separators, inset control bevels, and visible focus outlines. Allow rows to grow with their content. Check narrow and wide windows in English and Arabic, both themes, keyboard focus, and download and error states. Look for blank text, moving separators, clipped focus or help content, and scroll jumps. Keep the eager list if it meets those checks and performs well after repeated **Show more** clicks. If expanded lists prove costly, measure smaller batches or pagination before revisiting offscreen containment.
